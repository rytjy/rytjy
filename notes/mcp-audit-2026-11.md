# 阴性也是结果：我给两个 MCP server 做了一次审计

> rytjy · 2026-11-25 · 中文
> 两个案例的完整记录：`audit/mcp/cases/`。filesystem 是实测，fetch 是静态审查。
> 所有数字标了来源与日期；没跑通的测试一律写「未运行」。

MCP 的下载量已经是千万级。它把两样东西直接交到模型手里：**文件系统**和**网络**。这两样恰好是攻击面最厚的两样。

所以我想知道：这些 server 到底挡不挡得住最基本的三类越界——读到工作目录外、访问内网、执行任意命令。

我做完了两个目标。结果是**没有找到漏洞**。这篇文章写的就是这个「没有」是怎么来的，以及为什么它也算一次结果。

## 一、先定目标：按下载量，不按感觉

审计最怕的是挑一个「看起来有意思」的包，忙三天，发现全世界只有你一个人在用。

所以我用的第一条规则是**下载量优先**。数据取自 npm registry 与 PyPI 的官方 API，统计区间 2026-10-25 至 2026-11-23：

| 包 | 生态 | 月下载 | 选它的原因 |
|---|---|---|---|
| `@modelcontextprotocol/server-filesystem` | npm | 5,479,899 | 直接处理路径 |
| `mcp-server-fetch` | PyPI | 1,014,665 | 出网工具，SSRF 面最大 |
| `mcp-server-git` | PyPI | 440,783 | 子进程 + 仓库路径 |

顺带记下被我**排除**的，因为排除理由本身也是证据：

- `server-everything`（144 万/月）——官方**测试用**参考实现，本来就不是给生产用的；
- `server-sequential-thinking`（100 万/月）、`server-time`（68 万/月）——没有 I/O，没有攻击面；
- `server-memory`（133 万/月）——本地存储，风险低一档，留作备选。

一个包月下载五百万，意味着**这条路径上的任何一个判断，都会被放大五百万次**。

## 二、审计之前，先核产物

这一步经常被跳过，但它决定了后面所有结论有没有意义：**你测的到底是不是官方那份？**

npm 与 PyPI 都公布包摘要。以 filesystem 2.4.0 为例：

```
registry integrity: sha512-BoT8Gws5MsetfAey4vDyuzy8WYQES6mGYLSShuqSNGAC0X0NBV4p78/R78KfW4RkxtWz+zxhS9jwhzJrQUTt2Q==
local tarball      : sha512-BoT8Gws5MsetfAey4vDyuzy8WYQES6mGYLSShuqSNGAC0X0NBV4p78/R78KfW4RkxtWz+zxhS9jwhzJrQUTt2Q==
MATCH
```

fetch 那边是 sha256，同样一致（`91315261…314e4`）。

**如果这一步不一致，后面所有工作都作废。** 它不是形式主义——供应链攻击最常见的形态，就是你测的和你以为你测的，不是同一个东西。

## 三、案例 A：filesystem 2.4.0，实测阴性

### 方法

不经过 MCP 传输层，直接 import `dist/lib.js` 里的 `validatePath`，构造输入。理由：传输层本身不是这次要审的对象，绕过它能少一堆变量。

### 结果

| 输入 | 结果 |
|---|---|
| 允许目录内的普通文件 | **放行** |
| `allowed/../../etc/passwd` | **拒绝** — path outside allowed directories |
| 目录符号链接 → `/etc`，读 `etc/passwd` | **拒绝** — symlink target outside allowed directories |
| 文件符号链接 → `/tmp/…` | **拒绝** — 同上 |
| `/proc/self/environ` | **拒绝** |
| 目录内的符号链接 → 允许范围内的子目录 | 放行，解析到真实路径 |
| 父目录在允许范围内的新文件 | 放行（设计如此） |

三类越界全部被挡。源码里的注释也印证了这是一块被反复捶过的模块——NTFS 备用数据流（#5375）、Windows 设备名与结尾点号（#5444）、`~` 展开（#5180）、client Roots 越权（#3133），每一个都带着修复编号。

### 我自己犯的错，也记下来

第一轮我用了**相对路径**。结果返回的是 `.../allowed/sandbox/allowed/ok.txt`——路径被拼到了允许目录下面。

这不是漏洞，是设计：相对路径会被拼到每一个允许根目录。**但它说明了一件事：测试用例写错的时候，行为会看起来像正常放行。** 如果我当时没看返回值、只看「没报错」，就会把一个无效测试当成通过。

所以规则加一条：**每个「放行」都要打印实际解析到的路径**，不能只看有没有抛异常。

### 我没测的，不许当成安全

- TOCTOU：校验完之后把目录换成符号链接。代码说由 `pinned-directory` 处理，**我没实测**。
- Windows 专有路径（UNC、设备名、备用数据流）：不是我的平台。
- 递归遍历的条目级校验：读了代码，没跑。

## 四、案例 B：fetch 2026.11.18，只做了源码审查

这个案例我要说清楚状态：**静态审查完成，运行测试阻塞**。

源码里能定位到五道防线：

1. **每个请求发出去之前**，用 `raw_host`（ASCII/IDNA 形式）解析地址再判断。注释解释得很具体：用解码后的 Unicode 名字检查，getaddrinfo 会用另一套编码重新编码，检查的和连上的可能不是同一个名字。
2. **私网段是显式列的**，不依赖 `is_global` 的表：`127.0.0.0/8`、`169.254.0.0/16`、`10/8`、`172.16/12`、`192.168/16`、`100.64/10`（阿里云的 `100.100.100.200` 就在这一段）、`::/96`、`fc00::/7`、`fe80::/10`，另外 IPv4-mapped 与 NAT64 按里面裹的那个 IPv4 判断。
3. **连接时再查一遍**，并且只连检查过的地址。这一条是防 DNS rebinding 的关键——只在域名解析那一刻检查，等于没检查。
4. **重定向自己处理**，不用库的自动跟随：每一跳都要重新过硬钩子，否则一个公网地址 302 到内网就绕过去了。
5. 允许私网连接的开关**默认关闭**。

看起来是硬的。但**「看起来」不是结论**。

我原本想跑的三组用例：本地 `127.0.0.1` 是否被拒、`169.254.169.254` 是否被拒、公网跳转到内网是否被拒。

结果卡在环境：依赖下载反复中断。我试了「把第三方依赖打桩、直接加载模块」，依次卡在三个点上，最后停在版本元数据。**到这里我停了**——再往下，测的就不是它，而是我写的桩。

## 五、为什么阴性结果值得写

因为一个诚实的「没找到」，比一个含糊的「应该没问题」有用。

具体有三点：

1. **它把「不知道」变成「知道到这里」**。下载量五百万的一个包，路径校验挡住了三类越界——这是一个可以被别人复用的结论，不是我的感觉。
2. **它给下一次节省了时间**。同样的检查清单，换个包就能跑；阴性本身就是「这个方向不值得再投入」的证据。
3. **它训练的是方法，不是运气**。能不能找到洞，很大程度取决于运气；能不能把过程写清楚、让别人复现，是能力。

## 六、一份可以直接抄的清单

对着任何一个 MCP server，按这九条走：

- **工具描述**：description 里能不能藏指令？
- **路径**：`..`、绝对路径、符号链接、工作目录之外、`/proc` 这类特殊文件？
- **网络**：内网地址、`file://`、重定向后是否**重新**校验、DNS rebinding？
- **命令**：`shell=True`、字符串拼命令、参数没加引号？
- **鉴权**：HTTP 传输默认有没有鉴权？OAuth 能不能绕？
- **资源 URI**：`file://` 资源能不能越界？
- **工具输出**：server 返回的内容，能不能变成给模型的指令？
- **供应链**：版本 pin 了吗？有没有 postinstall？
- **日志**：凭据会不会写进日志？

每一条都要能给出**文件、行号、复现命令**。给不出，就不算发现。

## 七、披露纪律（比技术更重要）

真发现了什么，顺序是固定的：

1. 先读 `SECURITY.md`；
2. 走仓库的私密漏洞报告通道；
3. 没有通道就发邮件；
4. **不公开未修复的细节**，默认等 90 天；
5. 公开时只写方法、影响和已修复项，不写可直接复制的利用步骤。

把一次发现变成一次事故，只需要一步：提前公开。
