## 源码审查（四点）

1. **repo_path 是否允许任意目录**：`--repository` 是可选参数；不给时 `validate_repo_path` 直接 return（server.py:890-908，注释明写「every repository the server process can reach is in scope」）。给了就 `resolve()` 后 `relative_to` 判定——符号链接与 `..` 都在 resolve 后判。
2. **命令注入 / shell=True**：全文没有 `subprocess`、`shell=True`、`os.system`；所有 git 调用走 GitPython（`repo.git.*`，参数列表形式）。另有一组 flag 注入守卫：目标/范围端点以 `-` 开头即 `FlagInjectionError`（server.py:422/435/609/613/693/764/845/1104/1108）。
3. **.git/config 里的凭据**：`git_remote` 返回前会去掉 query 与 fragment（`_redact_query_and_fragment`，server.py:1172/1240），URL 含换行直接拒（`_remote_url_has_newline`，:1248）。
4. **hooks 能否执行**：`harden_repo`（server.py:332）在打开仓库后立刻执行，通过 `GIT_CONFIG_COUNT` 覆盖 `core.hooksPath=/dev/null`、`core.fsmonitor=false`、`commit.gpgSign=false`、`gc.auto=0` 等，并读回 `core.hooksPath` 确认覆盖生效（git < 2.31 直接拒）；再枚举仓库自定义的 filter/merge driver 并逐个覆盖为空命令。

## 补测（同日 13:0x）：hook / bare / submodule / 未配 --repository

脚本 `runtime_test2.py`、`runtime_test3.py`，输出 `runtime_out2.txt`、`runtime_out3.txt`（submodule 的 clean 驱动用一次性脚本补测，结果见下 C 组）。

| # | 用例 | 做法 | 结果 |
|---|---|---|---|
| H1a | 真实 pre-commit hook（基线） | `core.hooksPath` 指向含 `pre-commit`（touch marker）的目录，普通 commit | **hook 执行**（marker 出现） |

| H3 | submodule 存在时加固 | 加一个本地 submodule，harden 后跑 `git_status` | 成功；`_submodule_drivers` 能枚举 submodule 自己的驱动 |

| C2/C3 | 加固后同一操作 | `repo.git.add(A=True)`（super 上） | 成功；**marker 未出现**；枚举到 evil3 的两个键 |
| H4 | 未配 `--repository` | `validate_repo_path(/etc, None)` | 直接通过（文档写明的行为，不是缺陷） |

一个边界（记录，不算洞）：
- **加固发生在打开仓库那一刻**。如果 submodule 的配置在 `harden_repo` **之后**才被写入（例如另一个进程改了 `.git/modules/.../config`），新驱动名不在已生成的覆盖清单里（实测 H3d：后写入的驱动没被枚举）。要利用它，攻击方需要在会话期间持续写仓库内部文件——本次没有验证这条链路是否可达。
- T4 的 `InvalidGitRepositoryError` 是守卫在比较「是否 allowed 自己的 git dir」时打开 allowed 失败所致（`git.Repo(allowed)`），属 fail-closed；若 `--repository` 指向的是仓库根（正常配置）就不会走到这个分支。

## 结论

- 产物一致性：sha256 与 PyPI MATCH。
- 在**配置了 `--repository`** 时：本文用例内的路径逃逸（`..`、绝对路径、符号链接）全部被拒；flag 注入被拒；仓库自带 filter 在 GitPython 路径下被空命令覆盖（未执行），而未加固基线证明该攻击真实可行。
- 未配置 `--repository` 时没有任何限制——这是文档写明、不是缺陷；部署时是否该给默认值，属使用方选择。
- 真实 hook 与 submodule 的 clean 驱动两条链：未加固时都能执行（基线已证），加固后都未执行。
- 不含 0day，不构成安全背书。
