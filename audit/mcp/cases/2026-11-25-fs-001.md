## 方法

不经过 MCP 传输层，直接 import `dist/lib.js` 的 `validatePath`，构造输入：

```js
import { validatePath } from './package/dist/lib.js';
const A = [root + '/sandbox/allowed'];
await validatePath(p, A, 'read');
```

## 结果（7 个输入）

| 输入 | 实测 |
|---|---|
| `sandbox/allowed/ok.txt`（绝对路径） | **允许** → 解析到 allowed/ok.txt |
| `allowed/../../etc/passwd` | **拒绝** — «path outside allowed directories» |
| 符号链接目录 → `/etc`，读 `etc/passwd` | **拒绝** — «symlink target outside allowed directories: /etc/passwd» |
| 符号链接文件 → `/tmp/mcp-audit-secret.txt` | **拒绝** — 同上 |
| 目录内符号链接 → `allowed/sub` | **允许**，解析到 allowed/sub |
| 不存在的新文件（父目录在 allowed 内） | **允许**（符合设计：ENOENT 走父目录校验） |
| `/proc/self/environ`（绝对路径，允许范围外） | **拒绝** |

> 注：首轮我用了**相对路径**，被 `resolveRelativePathAgainstAllowedDirectories` 拼到 allowed 目录下（返回 `.../allowed/sandbox/allowed/ok.txt`），那次结果无效，已作废重跑。相对路径会被拼到每个 allowed 目录 —— 这是设计，不是缺陷，但记下来。

## 判定

在 **2.4.0 的路径校验层**，未发现可复现的越界读取。源码注释显示这几类问题历史上被修过：NTFS ADS（#5375）、Windows 设备名/尾点（#5444）、`~` 展开（#5180）、client Roots 越权（#3133）——与实测一致。

## 未覆盖（不许当成「安全」）

1. **TOCTOU**：validatePath 之后把目录换成符号链接 —— 代码称由 `pinned-directory.js` 处理，**未实测**。
2. **Windows 专有路径**（UNC / 设备名 / ADS）：非本平台，未测。
3. 多个 allowed 目录之间的歧义（相对路径在多个 root 下的落点）。
4. 启动参数本身是符号链接时的 realpath 行为。
5. 递归遍历（`search_files` / `list_directory`）的条目级校验：代码逐条 validatePath（server.js:542），**未实测**。
